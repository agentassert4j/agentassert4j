# 给 AI 装上行为回归回路

> 面向 AI 宿主集成者与 harness 开发者的人读评估：为什么确定性判定天然适配 AI 自修循环，
> 以及如何负责任地驱动 MCP 面。机器契约（manifest descriptions、错误包络、JSON schema）以
> 工具面自描述为准，本文讲的是选型论证与使用纪律。
> 配套：[OPERATIONS §6.2 MCP 接入](../OPERATIONS.md)、[README](../README.zh.md)。

## 一、自修循环缺的一环

让 AI 自己改提示词、自己跑测试、自己迭代，最大的风险不是它改不好，而是**它改坏了别处而不自知**：
提示词一处收紧，另一个任务的工具选择翻了；工具描述换个说法，参数格式崩了。模型当场看自己的
输出「挺好的」，因为没有一把尺子告诉它「相对你上一次认可的行为，这里变了」。

AgentAssert4j 补的就是这一环：把「行为是否还是原来那样」变成**确定性的二值判定**，AI 拿到的不是
一段需要再解释的评价，而是可编程消费的事实。

## 二、为什么确定性判定对 AI 特别友好

- **二值、可复现**：PASS / CHANGED 由四维结构指纹（工具调用集合、参数类型、输出字段路径与类型，
  以及钉入基线的内容规则与行为约束）确定性算出——同一输入任何时刻重判结果相同。AI 不需要处理
  「这次 82 分上次 85 分」式的评分漂移，也没有「评审模型今天心情」这类噪声。
- **零调用判定**：check / diff 不花一次 LLM 调用、不需要 API Key——自修循环里可以高频跑，
  只有显式的 re-drive（受控复核）才花真实调用且预算池封顶。
- **机器契约完备**：每份报告是单行 JSON（schema 标签齐全）；失败时错误包络（`error/1`）带
  `errorCode` / `hints[]` / `nextAction`——**下一步动作是自解释的**，AI 宿主不需要说明书就能自愈。
- **门禁语义清晰**：退出码 0/1/2 三分（无差异 / 有差异待人裁决 / 环境与证据问题），循环逻辑
  直接分支，不存在灰区。
- **「一样不一样」与「好不好」分离**：判定只回答前者。方向判断留给上游策略或人——这对 AI 是
  保护而不是限制：你不会想让自己的优化循环建立在一个会替你做价值判断的黑箱上。

## 三、循环怎么转

```
record（真实交互，三协议 wire JSON 原样入）
  → check / diff（对照认可形态集合，零调用判定）
  → CHANGED → 落候选 → 人（或被授权流程）accept 入集 / reject 丢弃
  → 复检绿（PASS (shape i of n)）→ 继续下一轮迭代
  → audit 对账（每笔治理写：动词/主体/时间/代码锚）
```

两个对迭代期特别有用的语义：

- **草稿不挡门**：判定只读每个调用点的**最新执行**——AI 一轮里试错的中间草稿不会把整个循环判红，
  早期未认可执行以 `unapprovedEarlier` 计数透明披露。
- **稳定性探针**：入集（accept）之前用 member-check 量稳定性——`matched k of N` 计数 + 命中会话
  名单。读数看计数：近邻 `matched 2 of 3` 是稳定复现；`1 of N` 命中一条远古会话是考古不是证据。
  JSON 的 `isMember` 布尔只表示「历史任一命中」，不承载阈值——**AI 消费者 accept 前以计数为准，
  不以布尔为准**。

## 四、治理纪律（AI 侧的自我约束）

- **身份申报**：治理动词（establish / accept / reject / rollback）必带 `approver`，AI 用
  `agent:<name>` 申报自己；缺 approver 的治理写被服务端直接拒绝。
- **变异动词在人授权下使用**：record / check / diff / report / verify 随时可自主调用；改变基线
  真相的动作（establish / accept / rollback）应在人的指示或被授权的流程内执行——manifest
  descriptions 对每个动词写明了这一要求。
- **携带代码锚**：accept 时带 `ref`（如当前 HEAD）几乎零成本，却让 audit 的每笔治理写都能回答
  「这个行为最后一次被认可是在哪个提交」——自修循环的完整审计链就此闭合。
- **共享库三规则**：与别的宿主共用一个库时——`--ci` 对未建档键 fail-closed 是设计不是故障；
  各判自己的域（check/diff 用 task/invocation 缩域）、establish 自己的键；全库门禁的前提是库里
  每个键都已建档。

## 五、边界如实

- 判定不评「更好还是更坏」；措辞差异永不进判定（只在报告中作低置信参考）。要钉措辞就声明内容
  规则（关键词/正则），且声明在**钉入基线的时刻**绑定。
- 规则与行为约束只对「钉入了该声明的基线」生效——候选侧临时改规则文件不会改变判定。
- 共享调用点多形态是正常公民：每个形态认可一次，凡以认可形态收尾的链复检为绿；回滚恢复的是
  整个集合快照。
- 框架从不驱动你的产品执行（re-drive 是受控复核，不是产品重跑）；录制失败宁可丢数据不阻塞业务。

## 六、接入

17 个工具镜像 CLI 动词：`record`（摄取入口，openai-chat / anthropic-messages / openai-responses
三协议原始 wire JSON）、`check` / `diff` / `report` / `verify` / `export` / `doctor` / `rules` /
`graph` / `record-show`、治理四动词（`establish` / `accept` / `reject` / `rollback`）+ `audit`、
`member-check`、`re-drive`。stdio 传输、单 jar 启动，
注册配方与客户端矩阵见 [OPERATIONS §6.2](../OPERATIONS.md#62-mcp-接入ai-自主验证回路)。
